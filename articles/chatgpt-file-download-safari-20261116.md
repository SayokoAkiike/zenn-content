## はじめに

ChatGPTに修士論文のWord草稿（DOCX）を作ってもらったところ、リンクを押してもダウンロードできませんでした。コンテンツブロッカーをオフにしても改善せず、英数字のファイル名に変えたら成功。そこで「日本語ファイル名が原因？」と思ったのですが、追加実験で予想外の結果になりました。

この記事は、**2026年11月16日にSafari上のChatGPTで行った一連のユーザー側検証**を記録したものです。OpenAI内部の実装や障害原因を特定した報告ではありません。なお、修論の内容や個人情報は公開しません。

## まず観測した現象

- 最初の `修論_草稿_261116.docx` のリンクはダウンロードに失敗。
- 別名の `thesis_draft_20261116.docx` は成功。ZIP版も用意したが、成功を確認したのはWord版。
- 最初のリンクを再試行しても、その時点では失敗。
- 後に**同じ元リンクが成功**した。
- 一方、**ファイルビューア内のダウンロードボタン**は、一瞬読み込み表示になるものの保存が始まらない現象が残った。

最後の点が重要です。**チャット本文のリンク**と**ビューアのダウンロードボタン**は、ユーザーから見た挙動が異なりました。ただし両者の内部APIが異なるかどうかは未確認です。

## 実験1：名前・サイズを変えてみる

| 条件 | 結果 |
| --- | --- |
| 英数字・小容量DOCX | 成功 |
| 日本語・小容量DOCX | 成功 |
| 半角スペースを含むDOCX | 成功 |
| 日本語・長い名前のDOCX | 成功 |
| 英数字・約534KBのDOCX | 成功 |
| 日本語・約534KBのDOCX | 成功 |

**6/6成功**。少なくとも、このテストでは日本語名・空白・約534KBというサイズは失敗の必要条件ではありませんでした。なお、同じファイル名でも生成・登録されたファイルは別物なので、「名前に絶対問題がない」とまでは言えません。

## 実験2：ファイル内容と参照を切り分ける

次に、元ファイルと同じ内容のコピーや、保存し直したファイルを比較しました。

| 条件 | 結果 |
| --- | --- |
| 元ファイルとバイト単位で同一・英数字名 | 成功 |
| 元ファイルとバイト単位で同一・日本語名 | 成功 |
| Word形式で再保存した版 | 成功 |
| 完全新規の小容量DOCX | 成功 |
| 元ファイルをZIPに格納 | 成功 |
| **以前失敗した元リンクの再試行** | **成功** |

**6/6成功**。ここで注目したいのは、元リンクが「失敗→失敗→成功」と変化したことです。

新しいファイルの作成が復旧を引き起こしたのか、時間経過やセッション状態が関係したのかは分かりません。HTTPステータスや通信ログを記録していないため、原因を断定することはできません。

## 公開されている類似報告

調べると、同じ時期に関連しそうなIssueが公開されていました。

### 1. [Issue #48862](https://github.com/openai/codex/issues/48862)

生成ファイルのダウンロードで `ace_pod_expired` やHTTP 404が出た後、元のリンクが再び使えるようになったという報告。**元リンクの挙動が時間とともに変わる**点は今回と似ています。ただしこちらの環境ではエラーコード未取得です。

### 2. [Issue #60370（2026年11月9日）](https://github.com/openai/codex/issues/60370)

ChatGPT Webで生成ファイルのリンクがHTTP 404 `Library file not found` を返す一方、別のファイル保存画面からは取得できたという報告。会話内リンクの参照情報とファイル実体の対応付けが調査対象として挙げられています。**報告者の推測であり、確定した根本原因ではありません。**

### 3. [Issue #61007（2026年11月12日）](https://github.com/openai/codex/issues/61007)

Webとデスクトップアプリで生成ファイルのダウンロードに失敗する報告。こちらも今回と同じ障害であるとは確定していません。

また、[OpenAI公式ヘルプ](https://help.openai.com/en/articles/7996703-troubleshooting-chatgpt-error-messages)には、生成ファイルの「Download failed / File Not Found」に対する一般的な対処が記載されています。

## 現時点の仮説

今回のデータから言えるのは、**ファイル内容の破損や日本語ファイル名だけでは一連の失敗を説明しにくい**ということです。ファイル参照の一時的不整合、認証・セッション状態、ビューア側の保存開始処理などが候補になります。

ただし、次の点はまだ検証していません。

- SafariのNetworkタブで、ビューアのボタン押下時に通信が発生するか
- HTTP 200/403/404/5xxのどれが返るか
- コンソールにJavaScript例外が出ているか
- 同じタイミングにChromeなど別ブラウザで再現するか

したがって「ChatGPTサーバーのバグだ」と結論づけるのは早いと思います。

## 同じ問題に遭遇したら

まずは**ビューアではなくチャット本文のファイルリンク**を試し、失敗したら新しい名前で再生成してみるのが暫定的な回避策です。今回の実験では有効でしたが、誰にでも効く保証はありません。

原因調査まで行うなら、Safariの「開発 → Webインスペクタ → ネットワーク」を開き、**記録を開始してから**ダウンロードボタンを押します。通信が出ない場合はUI処理、HTTP 404なら参照解決、200なのに保存されないなら保存開始処理など、次の調査対象を絞れます。

公開Issueに添付する場合は、Cookie、認証ヘッダー、署名付きURL、会話ID、メッセージID、ファイルの中身などを必ず伏せてください。

## おわりに

今回面白かったのは、最初にもっともらしく見えた「日本語ファイル名が原因」という仮説が、6件の追加検証ですぐ崩れたことでした。さらに、同じ元リンクが後から成功したため、**ファイルそのものの問題と、そのファイルへ到達する経路の問題を分けて考える必要**が見えてきました。

次はSafariの通信ログを取得して、ビューアで何が起きているのかを確認したいところです。もし同じ症状を経験した方がいれば、ブラウザ、ファイル形式、チャットリンクとビューアのどちらで失敗したかを教えていただけると参考になります。
