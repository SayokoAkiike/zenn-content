音声認識モデルのWhisperには、音声にない文章を出力してしまう癖があります。無音や雑音の区間に、それらしい一文が出てくる現象です。

これを追加学習なしで、重みを少し書き換えるだけで抑えられないか。手元でそんな実験をしていて、その途中で日本語の聞き取りへの影響を確かめました。この記事はその検証記録です。

先に結論を書いておきます。

- Whisper smallのデコーダで、注意ヘッドを**1個だけ**弱める編集を3通り試した
- 日本語の合成音声120文で比べたところ、**どの編集も編集なしより良くならなかった**
- ただし差はごく小さく、誤りが増えた分の大半は**1つの文**から出ていた

効果は出ませんでしたが、重みを編集して比べる手順は一通り回せたので、コードと一緒に残しておきます。

## なぜ注意ヘッドを1個だけ編集するのか

Whisperは、音声を読み取るエンコーダと、文字を1つずつ出していくデコーダでできています。デコーダの各層には注意ヘッドが並んでいて、それぞれが音声のどこを見るか、それまでに出した文字列のどこを見るかを計算しています。

音声にない文章が出てくるとき、デコーダは音声よりも、それまでに書いた文字列の流れに引っ張られているのではないか。そう考えて、文字列側を参照する自己注意ヘッドの寄与を弱めてみることにしました。とはいえ、ハルシネーション専用のヘッドがあると決めつけているわけではありません。

小さな編集から試す理由は単純で、追加学習よりずっと安く、元にも戻せるからです。重みを直接いじる発想は、以前このブログで紹介したWeight-Space Programmingの研究にも影響を受けています。

https://zenn.dev/akisayo/articles/weight-space-programming

## 編集のしかた：出力射影の列にα倍を掛ける

Whisper smallのデコーダの自己注意では、12個のヘッドの出力（64次元ずつ）が横に並んで768次元になり、`attn.out` という線形層で混ぜ合わされます。

つまり、`attn.out.weight` の列のうちヘッド1個分の64列にα倍を掛ければ、そのヘッドの寄与だけを弱められます。αが1なら元のまま、0.5なら半分、0なら完全に止めることになります。

実際に使ったコードはこれです。

```python
from contextlib import contextmanager

def head_columns(n_state, n_heads, head):
    if n_heads <= 0 or n_state % n_heads or not 0 <= head < n_heads:
        raise ValueError("Invalid head layout")
    width = n_state // n_heads
    return slice(head * width, (head + 1) * width)

@contextmanager
def edited_head(model, layer, head, alpha):
    import torch
    if not 0 <= alpha <= 1:
        raise ValueError("alpha must be between zero and one")
    weight = model.decoder.blocks[layer].attn.out.weight
    n_state = model.dims.n_text_state            # small では 768
    cols = head_columns(n_state, model.dims.n_text_head, head)  # 12ヘッド → 64列ずつ
    original = weight[:, cols].detach().clone()
    try:
        with torch.no_grad():
            weight[:, cols].copy_(original * alpha)
        yield
    finally:
        # 例外が起きても必ず元の重みに戻す
        with torch.no_grad():
            weight[:, cols].copy_(original)
```

`with` ブロックの中だけ重みが変わり、抜けると必ず元に戻ります。同じモデルを読み込み直さずに、編集なしと編集ありを交互に評価できます。

### 編集してよいヘッドを先に決めておく

候補を結果を見ながら選ぶと、いくらでも都合のいい編集が見つかってしまいます。そこで、編集してよいヘッドは、モデルの構造だけから最初に決めておきました。

```python
import numpy as np

def evenly_spaced_layers(n_layers, k):
    return sorted({int(round(x)) for x in np.linspace(0, n_layers - 1, k)})

def allowed_heads(n_text_layer, n_text_head, k_layers=4):
    """等間隔の4層 × ヘッド{先頭, 真ん中, 最後}。失敗例やスコアは一切見ない"""
    layers = evenly_spaced_layers(n_text_layer, k_layers)
    picks = sorted({0, n_text_head // 2, n_text_head - 1})
    return [(l, h) for l in layers for h in picks]

allowed_heads(12, 12)
# → 層 0, 4, 7, 11 × ヘッド 0, 6, 11 の12個
```

### 比べた3つの候補

この12個の中から、英語の開発用データで3通りの選び方を試し、それぞれ1つずつ候補を決めてありました。日本語では選び直していません。

| 条件 | 選び方 | 編集内容 |
|---|---|---|
| B0 | 編集なし | ― |
| H | ヘッドを止めて影響の大きいものを選ぶ | 層4・ヘッド0を α=0 |
| C | αを0〜1で探索する | 層7・ヘッド6を α=0 |
| W | LLMに実験記録を読ませて場所と倍率を提案させる | 層0・ヘッド11を α=0.5 |

Wは、Weight-Space Programmingの考え方を借りて、LLMに提案させたものです。ただし今回は、LLMに任せたのは上の12ヘッドとαの選択だけで、重みを自由に書き換えさせてはいません。

英語側の選び方の詳細は、この記事では扱いません。ここで見たいのは、英語で選んだ編集が日本語の聞き取りを壊していないか、という点です。

## 評価用の日本語音声を120文つくる

手元に、正解の文がはっきりしている日本語の音声がたくさんあるわけではありません。そこで、オープンソースの音声合成モデルVoxCPM2で評価用の音声を作りました。

文は4種類を30文ずつ、合計120文用意しました。

| 種類 | 例 |
|---|---|
| 通常文 | 雨の日は足元が滑りやすいので、ゆっくり歩いてください。 |
| 言い直し | 来週の月曜日、いえ、火曜日にお伺いします。 |
| 数字 | 合計金額は、三千五百二十円になります。 |
| 間のある文 | それでは、……少しお待ちください。 |

言い直しや間のある文を入れたのは、話し言葉らしい音声で編集の副作用が出やすいと考えたからです。

声は、事前に試聴して選んだ1本を参照音声にして、全文で同じ話者になるようにしました。試聴に使った3文は評価文に入れていません。生成部分の中身はこれだけです。


各文1テイクで、出来の悪いものを選び直すこともしていません。都合のいい音声だけを残すと、評価が甘くなるからです。

Google ColabのT4 GPUで生成して、120本で合計9分43秒、1本あたり2.4〜7.7秒になりました。生成にかかった時間は約20分です。Whisperの入力窓の30秒を超える音声はありません。

## 採点のしかた

Whisperは公式の `openai-whisper` パッケージのsmallを使い、4条件で同じ設定のまま文字起こししました。

```python
for group, patch in [('B0', None), ('H', (4, 0, 0.0)),
                     ('C', (7, 6, 0.0)), ('W', (0, 11, 0.5))]:
    with edited_head(model, *patch) if patch else nullcontext():
        with torch.inference_mode():
            result = whisper.decode(model, mel, whisper.DecodingOptions(
                language='ja', task='transcribe', temperature=0,
                fp16=False, without_timestamps=True))
```

`temperature=0` にして、毎回同じ結果が出るようにしています。認識にかかった時間は4条件合わせて約2.3分でした。

採点は、指定した文と認識結果の文字単位の編集距離です。NFKC正規化をかけて、空白と句読点を取り除いてから比べました。

```python
PUNCT = re.compile(r'''[\s、。，．・…‥！？!?「」『』（）()\[\]【】〜~\-—,.:;"'’“”]+''')

def norm(x):
    return PUNCT.sub('', unicodedata.normalize('NFKC', x))

def distance(a, b):  # レーベンシュタイン距離
    row = list(range(len(b) + 1))
    for i, x in enumerate(a, 1):
        new = [i]
        for j, y in enumerate(b, 1):
            new.append(min(new[-1] + 1, row[j] + 1, row[j - 1] + (x != y)))
        row = new
    return row[-1]
```

ひとつ注意があります。正解として使っているのは、合成に渡した文です。人が音声を聞いて確かめた文ではありません。音声合成が読み間違えた場合も、Whisperの誤りとして数えられてしまいます。なので、ここで出す数字は正式な文字誤り率ではなく、**指定した文との不一致率**として読んでください。

## 結果

### 全体

| 条件 | 誤り文字数 / 文字数 | 不一致率 |
|---|---|---|
| B0（編集なし） | 325 / 2311 | **14.06%** |
| H（層4・ヘッド0, α=0） | 335 / 2311 | 14.50% |
| C（層7・ヘッド6, α=0） | 334 / 2311 | 14.45% |
| W（層0・ヘッド11, α=0.5） | 334 / 2311 | 14.45% |

編集なしのB0がいちばん良く、どの編集もそれを上回りませんでした。差は9〜10文字です。

### 種類別

| 種類 | B0 | H | C | W |
|---|---|---|---|---|
| 通常文 | 5.1% | 5.4% | 5.3% | **5.0%** |
| 言い直し | 10.6% | 10.6% | 10.8% | 10.6% |
| 数字 | **36.9%** | 38.6% | 38.4% | 39.6% |
| 間のある文 | 8.3% | 8.3% | 8.3% | **7.8%** |

種類ごとに見ると、Wは通常文と間のある文でわずかにB0より良く、数字の文で負けていました。差はほぼ数字の文から来ています。

数字の文は、どの条件でも不一致率が4割近くあります。ただこれは、`三千五百二十円` が `3,520円` と書かれるような表記の違いでかなり水増しされています。

そこで、年・月・日・時・分・秒・円・人・回の直前にある漢数字と、文全体が数字の場合だけ算用数字にそろえて、採点し直してみました。

| 条件 | 数字表記をそろえた後 |
|---|---|
| B0 | **11.31%**（261 / 2308） |
| H | 11.74%（271 / 2308） |
| C | 11.70%（270 / 2308） |
| W | 11.70%（270 / 2308） |

この規則は結果を見てから足したものです。ただ、全条件に同じ規則を当てているので、順位は変わりません。

### 違いが出たのは120文中20文だけ

4条件の認識結果を1文ずつ並べると、どこか1つでも結果が違った文は120文中20文で、残りの100文は4条件とも完全に同じ文字列でした。

そして、H・C・Wが誤りを増やした分のうち8文字は、次の1文から出ていました。

```text
指定文: 一日三回、一回二錠を、七日分お出しします。

B0    : 1、2、3、1、2、3を7日分を出しします。
H/C/W : 1、2、3、1、2、7、7、
```

B0も正しく読めてはいませんが、編集した3条件は途中で文が途切れています。選び方も編集した場所も違う3つの編集が、まったく同じ崩れ方をしているのは面白いところです。数字が続く文で、それまでの文字列への参照を弱めたことが効いた可能性はありますが、1文だけでは何とも言えません。

逆に、Wのほうが良かった文もあります。

```text
指定文: えっと、今、手元に資料がないので、確認して折り返します。

B0    : 今、手元に資料がないので確認しており返します。
W     : えっと、今手元に資料がないので確認しており返します
```

B0は冒頭の「えっと」を落としていますが、Wは拾えています。ほかに、Wが `お進みください` を正しく漢字で書けた文もあれば、`キログラム` を `kg` と書いて減点された文もありました。違いの多くは表記の揺れで、内容まで変わっているのは上の途切れた1文くらいでした。

## 分かったこと

- 英語で選んだヘッド1個の編集は、今回の日本語120文では**良くも悪くもほとんど効かなかった**
- 差が出たのは数字の多い文で、1文の途切れが全体の差のほとんどを占めていた
- 3つの選び方による違いは、この規模では見分けられなかった

日本語の聞き取りを大きく壊していないことは確かめられた、とも言えます。ただ、良くなったと言える材料もありません。

## この検証の限界

- **正解の文を人が確かめていない**：例えば `体温は三十六度八分でした` が `台本は36度8分でした` になった文は、音声合成が読み間違えたのか、Whisperが聞き間違えたのか分かりません
- **合成音声で、話者が1人だけ**：実際の録音や、ほかの声でも同じとは限りません
- **120文は小さい**：9文字程度の差は誤差の範囲で、統計的に差がないと言えるわけでもありません
- **本題のハルシネーションは測っていない**：今回はすべて話している音声です。無音区間で文章が出る現象が減ったかどうかは、この記事の範囲外です

## 次にやりたいこと

まずは120本を自分の耳で聞いて、実際に何と言っているかを書き起こすことです。そのための確認用のページは作ってあるので、そこから正式な文字誤り率を出し直したいと思います。

そのうえで、無音や雑音だけの音声を入れたときに、編集で余計な文章が減るのかを確かめたいです。ヘッドを1個いじるだけでは足りないのか、そもそもヘッド単位で考えるのが違うのか。そのあたりが見えてきたら、また書きます。
