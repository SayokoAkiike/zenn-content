Zennで書いた記事をX（旧Twitter）で紹介しようと思い、URLをコピーして貼り付けた。

すると、URLが消えて記事タイトルだけになった。

……あれ、これってちゃんとリンクになってる？

普段なら気にせず使っているコピー＆ペースト。でも考えてみると、ちょっと不思議です。

**コピーしたのはURLなのに、なぜ貼り付けるとタイトルに変わるのでしょうか？**

調べてみると、実はこの現象、ブラウザの便利機能と、クリップボードの意外と複雑な仕組みが関係していました。

今回は、HTMLやMarkdown、クリップボードのデータ形式、リッチテキストエディターの仕組みまで、なるべく直感的に解説してみます。

## 1. 犯人はMicrosoft Edge……かもしれない

最初に調べて驚いたのですが、実はMicrosoft Edgeには、URLをコピーすると、そのページのタイトルをハイパーリンク付きで貼り付ける機能があります。

これはバグではなく、Microsoftが公式に提供している機能です。

例えば、ブラウザのアドレスバーから次のURLをコピーしたとします。

`https://zenn.dev/`

ところが、対応するアプリに貼り付けると、

[Zenn](https://zenn.dev/)

という具合に、ページタイトルを持ったリンクとして表示されることがあります。

つまり、**URLが消えたのではなく、URLを表示しない形式に変換されていた**わけです。

Microsoftの公式ドキュメントでも、EdgeのアドレスバーからコピーしたURLは、既定でページタイトル付きのハイパーリンクとして貼り付けられると説明されています。

もちろん、貼り付け先のアプリによって結果は異なります。すべてのケースがEdgeの機能によるものとは限りません。

参考：[Microsoft Support — Microsoft Edge での URL のコピーと貼り付けの改善](https://support.microsoft.com/ja-jp/edge/improved-copy-and-paste-of-urls-in-microsoft-edge)

では、なぜこんな変換ができるのでしょうか？

実は、私たちが普段使っているクリップボードは、単純な「文字列の一時保管場所」ではないからです。

## 2. クリップボードは、ただの文字列保存場所ではない

ここが今回、一番面白いと思ったところです。

普段、私たちは `Ctrl + C` を押すと「選択した文字がコピーされる」と考えています。

でも、実際には文字列以外の情報も扱えます。

例えば、Wordで太字や色付きの文章をコピーすると、別のWord文書にも書式付きで貼り付けられますよね。

Webサイトの表をコピーして、Excelに表として貼り付けられることもあります。

なぜそんなことができるのでしょう？

答えは、**クリップボードが複数のデータ形式を扱えるから**です。

Web技術の世界では、データの形式を識別するためにMIMEタイプというものが使われます。

代表的な例を見てみましょう。

| MIMEタイプ | どんなデータ？ |
|---|---|
| `text/plain` | 書式のない普通のテキスト |
| `text/html` | HTML形式のテキスト |
| `image/png` | PNG画像 |

例えば、同じ文章が次のような複数の表現でクリップボードに用意されている場合があります。

**プレーンテキスト**

```text
Zennの記事はこちら
```

**HTML**

```html
<a href="https://zenn.dev/">
  Zennの記事はこちら
</a>
```

前者はただの文字列ですが、後者にはリンク先のURLが含まれています。

つまり、表示される文章は同じでも、内部の情報が異なるわけです。

さらに、ひとつのコピー操作で、同じ内容のプレーンテキスト版とHTML版の両方を提供することもできます。

貼り付け先のアプリは、その中から自分が扱える形式を選択することができます。

イメージとしては、同じ書類をPDF版とWord版の両方で渡して、受け取った人が都合のよい方を使うようなものです。

この仕組みは、Web標準のClipboard APIでも扱われています。

参考：[MDN — Clipboard API](https://developer.mozilla.org/ja/docs/Web/API/Clipboard_API)

## 3. 同じリンクでも、実は中身が違う

ここで、もう少しHTMLとMarkdownについて見てみます。

例えば、次の3つは、見た目や用途が似ています。

**① 普通のURL**

```text
https://zenn.dev/
```

**② HTMLのリンク**

```html
<a href="https://zenn.dev/">
  Zenn
</a>
```

**③ Markdownのリンク**

```markdown
[Zenn](https://zenn.dev/)
```

HTMLとMarkdownでは、表示する文字とリンク先のURLが分離されています。

この違いが重要です。

HTMLの `<a>` は、リンクを作るための要素です。

`href` 属性にリンク先を指定し、タグで囲まれた部分を表示文字列として扱います。

一方、Markdownでは `[表示文字列](URL)` という書き方で同じようなリンクを表現できます。

ただし、**Markdownはクリップボードの標準的なHTML形式と同じものではありません。**

Markdownで書かれた文字列は、Markdownを解釈するソフトウェアによってリンクとして表示されます。

つまり、リンクがどう見えるかは、そのテキストをどのアプリが、どの形式として解釈するかによって変わります。

Webページのリンクをコピーしたとき、表示文字列だけでなく、リンク先まで保持できるのは、こうした構造化された情報を受け渡しできるからです。

参考：[MDN — HTMLのアンカー要素](https://developer.mozilla.org/ja/docs/Web/HTML/Reference/Elements/a)

## 4. 貼り付け先によって表示が変わるのはなぜ？

では、クリップボードに複数のデータ形式が入っていたとして、実際にどれが使われるのでしょうか？

ここで登場するのが、貼り付け先のエディターです。

例えば、一般的なテキストエディターでは、プレーンテキストとして貼り付けられることがあります。

一方、Wordのようなリッチテキストエディターでは、HTMLなどの書式情報を利用して、リンクや装飾を維持することがあります。

つまり、コピー＆ペーストは、

**コピー元が何を提供するか × 貼り付け先が何を受け取るか**

によって結果が変わるのです。

Webアプリケーションでは、貼り付け操作をJavaScriptで処理することもできます。

例えば、次のようなコードです。

```javascript
document.addEventListener("paste", (event) => {
  const clipboard = event.clipboardData;

  const text = clipboard.getData("text/plain");
  const html = clipboard.getData("text/html");

  console.log("Plain text:", text);
  console.log("HTML:", html);
});
```

このコードは、ユーザーが貼り付け操作をした際、取得可能なプレーンテキストとHTMLデータをコンソールに表示するものです。

ここで使っている `clipboardData` は、貼り付けイベントに付随するデータを扱うためのインターフェースです。

ただし、取得できる形式や内容は、ブラウザやコピー元によって異なります。

また、これは仕組みを説明するためのコードであり、今回のXでの挙動を実際に検証した結果ではありません。

## 5. リンクが本当に消えることもある？

さて、最初の疑問に戻りましょう。

URLを貼り付けたらタイトルになった。

このとき、リンク先の情報はどうなっているのでしょうか？

大きく分けて、次の3つのパターンが考えられます。

### パターンA：リンクはちゃんと残っている

例えば、

```html
<a href="https://zenn.dev/">
  Zenn
</a>
```

という形で保存されていれば、表示されているのは「Zenn」という文字だけでも、リンク先は保持されています。

これは正常なハイパーリンクです。

### パターンB：タイトルだけが残っている

一方、貼り付け先の処理によって、

```text
Zenn
```

という文字列だけになってしまう場合も考えられます。

この場合、リンク先の情報はありません。

画面上ではタイトルが表示されていても、クリックして移動することはできません。

### パターンC：リンクカードに変換されている

Webサービスでは、URLを解析して、タイトルや画像、説明文を含むリンクカードを生成することもあります。

これは単にHTMLのリンクを貼り付けるのとは別の仕組みです。

サービス側がURLからメタデータを取得し、独自のUIとして描画することがあります。

例えば、Webページのメタ情報には、次のようなものがあります。

```html
<meta
  property="og:title"
  content="小は大を兼ねる…!? SLMの有用性"
>

<meta
  property="og:description"
  content="小規模言語モデルの活用を考える"
>
```

これらはOpen Graphという仕組みで使われる情報です。

SNSなどでURLを共有したときのリンクプレビューに利用されることがあります。

つまり、「URLがタイトルになった」という同じ現象に見えても、

- クリップボードがリンク付きテキストを渡した
- エディターがリンクを変換した
- サービスがURLを解析してプレビューを作った

など、異なる処理が関わっている可能性があります。

**見た目が同じだからといって、中身まで同じとは限らない。**

Webアプリを作る上でも、意外と重要な視点だと思います。

## 6. なぜアプリはリンクを書き換えたり、削除したりするの？

ここまで読むと、ひとつ疑問が浮かびます。

「HTMLのリンクがあるなら、そのまま保存すればいいのでは？」

でも、実はそう単純でもありません。

ユーザーがコピーしたHTMLには、文字装飾だけでなく、さまざまな要素や属性が含まれている可能性があります。

例えば、外部から貼り付けられたHTMLを、何も確認せずそのままアプリ内に表示してしまうと、悪意のあるコードが混入するリスクがあります。

そこで、多くのWebアプリでは、受け取ったHTMLを制限・無害化する処理が必要になります。

こうした処理は**サニタイズ（Sanitization）**と呼ばれます。

ただし、サニタイズと、リンクを単純な文字列へ変換する処理は同じではありません。

例えば、不要な属性だけを取り除いて安全なリンクを残す設計もできますし、HTML全体を許可せずテキストだけを採用する設計もできます。

実装方針によって、リンク情報が残るかどうかが変わるのです。

つまり、リンクが消えるのは必ずしもバグとは限らず、**アプリの仕様や安全性のための処理による場合もある**というわけです。

## 7. URLをそのまま貼りたいときは？

ここまで仕組みを理解したところで、実用的な話も少し。

Microsoft EdgeでURLをそのまま貼りたい場合は、`Ctrl + Shift + V` が使えます。

これは、通常の貼り付けとは異なり、書式なしのテキストとして貼り付ける操作です。

Edgeの公式ドキュメントでも、URLをハイパーリンク付きタイトルではなくWebアドレスとして貼り付ける方法として案内されています。

また、Edgeの設定から、URLのコピー＆ペーストの既定形式を変更することもできます。

ただし、ショートカットキーの挙動や貼り付け結果はアプリによって異なります。

ブラウザ以外のアプリでは、貼り付け先独自の処理が優先される場合もあります。

リンクとして残っているか不安なときは、実際にリンク先を確認するのが確実です。

## 8. まとめ：コピペは、思ったより賢い

今回の疑問は、とても単純なものでした。

「URLをコピーしたはずなのに、どうして記事タイトルになった？」

でも、そこから見えてきたのは、

- クリップボードは複数のデータ形式を扱える
- HTMLでは表示文字列とリンク先を別々に保持できる
- 貼り付け先のアプリが、受け取った情報をどう扱うか決める
- エディター独自の変換やサニタイズで情報が変わることもある
- URLのプレビュー生成は、単なるコピー＆ペーストとは別の仕組み

という、Web技術のさまざまな要素でした。

普段何気なく使っている `Ctrl + C` と `Ctrl + V`。

たった2つのショートカットですが、裏側ではコピー元と貼り付け先の間で、データ形式の受け渡しや変換が行われています。

今回調べてみて、**コピー＆ペーストは単なる文字の移動ではなく、異なるアプリケーション間で情報を受け渡すためのインターフェースなんだな**と改めて感じました。

身近な機能でも、少し掘り下げてみると、なかなか面白いものですね。
